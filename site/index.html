Certificate Flow Film

One continuous camera move, with a single flashback, through a stylised 3D world: how a certificate is requested, issued and trusted in an Active Directory Certificate Services PKI. 109 seconds, 1920×1080, 30 FPS, no narration.

Watch

This is the 720p preview with captions. Full 1080p MP4 (release asset).

What the film shows

RDP path. The RDP server is issued a certificate from the RDPAuth template by 1SN0S Issuing CA 1, whose CA certificate was signed offline by the 1SN0S Root CA. The client validates the whole chain up to the root it already trusts.

TLS path. The web server is issued a certificate from the WebServer-TLS template by 1SN0S Issuing CA 2, signed by the same root.

One trusted root. Different templates can use different issuing CAs, but trust always anchors at the single Root CA. The private key never leaves the machine that generated it: the request is signed with it, and the request carries only the public key.

How it was made

Everything is generated from one story model in Python: scripted Blender (bpy) builds the scene and animation, EEVEE renders PNG sequences, and FFmpeg composites captions and sound-effect audio and encodes the film. A suite of automated checks (story consistency, PKI facts, motion limits, legibility, text contrast, frame sanity) acts as the discriminator against the generator; an adversarial review loop judged the story spec and the first animatic round only, and the film is gated on those automated checks.
